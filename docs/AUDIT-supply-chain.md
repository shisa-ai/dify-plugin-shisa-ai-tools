# Supply Chain Audit — Shisa AI Tools for Dify

## Snapshot

- Date: 2026-08-05
- Repository: `shisa-ai/dify-plugin-shisa-ai-tools`
- Branch reviewed: `main` plus `security/supply-chain-baseline`
- Ecosystem: Python 3.12, Dify Tool plugin
- Package authority: `uv.lock`
- Working tree at audit start: clean

## Install and release surfaces

- Development and CI dependencies are resolved by uv from `pyproject.toml` and `uv.lock`.
- CI uses `uv sync --frozen --no-install-project` and verifies the lockfile and exported `requirements.txt`.
- `requirements.txt` is a fully pinned, hashed export for the Dify package surface.
- Plugin packaging is manual; no automated publishing workflow or long-lived publishing token exists.
- Generated `.difypkg` files are excluded from Git.

## Direct dependencies

- `dify-plugin==0.9.0`
- `httpx==0.28.1`
- Development validation: `pyyaml==6.0.3`

The transitive tree, exact versions, artifact URLs, and hashes are recorded in `uv.lock`. A deterministic CycloneDX SBOM is generated by `scripts/generate_sbom.py`.

## Resolution controls

- Routine resolution cutoff: `2026-07-29T00:00:00Z`, seven days before this audit snapshot.
- Future routine lock refreshes must advance the cutoff to a reviewed timestamp at least seven days in the past.
- Emergency security updates may bypass the age gate only when the PR documents the vulnerability and reason.
- Git, URL, editable, local-path, and alternate-index dependencies are not used.
- CI consumes only the committed lockfile through frozen installs.

## GitHub Actions review

- Workflow token permission is `contents: read`.
- External fork workflows require maintainer approval.
- Only GitHub-owned actions and the explicitly approved `astral-sh/setup-uv` action are allowed at repository level.
- Every action is pinned to a full commit SHA.
- `pull_request_target` and `workflow_run` are rejected by `scripts/validate_workflows.py`.
- CI does not access credentials, call the live Shisa API, build a release package, or publish artifacts.
- Dependency changes receive a dependency-review job and required human review.

## Repository controls

- `main` requires PR review, current required checks, linear history, and resolved conversations.
- Force pushes and branch deletion are blocked.
- `v*` tags are protected.
- Secret scanning, push protection, Dependabot security updates, and private vulnerability reporting are enabled.

## Exceptions and open remediation

1. Tools `0.0.3` and its Translation API integration still require live validation in a non-production Dify workspace before release.
2. The Dify packaging CLI is not executed in CI. Any future release workflow must pin the CLI, use a protected release environment, avoid attacker-controlled triggers, generate and attach the SBOM, and provide provenance/attestation.
3. Routine Dependabot updates require the seven-day cooldown, lock refresh, tests, and human review. Emergency security updates may use the documented exception.
